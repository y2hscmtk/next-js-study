1.1. Next.js 란?
Next.js 는 React 만을 위한 프레임워크로, React를 더 효율적으로 사용하기 위해 개발됨

- 리엑트의 확장판(페이지 라우팅, 빌트인 최적화 기능, 등 효율적인 기능 제공)
- 카카오 웹툰, OP.GG 등이 사용중
- Next.js 는 라이브러리가 아닌, 프레임워크!
=> 주도권을 프레임워크가 지니며, 프레임워크가 허용하는 범위 내에서 기능 구현

1.2. 사전 렌더링 이해하기
Next.js 의 원리 파악 가능
사전 렌더링이란?
브라우저의 요청에 사전에 랜더링이 완료된 HTML을 응답하는 렌더링 방식
리엑트의 Client Side Rendering의 단점을 해결 가능 
서버에서 JS로 만들어둔 모든 페이지를 랜더링(HTML 페이지로 변환)한 뒤, 브라우저에 응답하는 방식

React.js 앱의 기본적인 랜더링 방식, 클라이언트에서 직접 화면을 랜더링 하는 방식
1. 서버가 빈 껍데이긴 index.html 파일을 보내게 되면, 브라우저가 사용자에게 빈 화면을 랜더링함
2. 서버는 이후 후속으로 JS Bundle(이 서비스에서 접근 가능한 모든 컴포넌트 코드가 존재)을 브라우저로 전송하고, 브라우저는 JS를 실행하여 화면을 채운다. (컨텐츠 랜더링)
3. 이후 사용자는 채워진 화면을 볼 수 있음
장점: 페이지 이동이 매우 빠르고 쾌적하다는 장점이 있다.(index.html 페이지 하나와 JS Bundle만을 사용하여 페이지를 구현하기 때문) -> 초기 접속 이후의 페이지 이동이 빠름
단점: 초기 접속 속도가 느려진다.(JS Bundle에 포함되는 데이터가 많아질수록 JS Bundle을 만들고, 브라우저가 실행하는 시간이 오래걸리기 때문 -> FCP(First Contentful Paint))

Next.js는 사전 랜더링 기술을 사용하여 FCP(사용자가 초기에 화면을 확인하는 순간)를 개선함
1. 서버에서 JS를 실행(랜더링)하고, 랜더링 된 HTML을 전송
2. 브라우저는 화면에 바로 랜더링 -> 사용자는 컨텐츠가 채워진 화면을 볼 수 있음 -> 웹 페이지에 인터렉션 JS가 처리하는 영역이기 때문에 상호작용(버튼 클릭)은 아직 불가능한 상태
3. 서버는 JS Bundle을 브라우저로 후속 전송 -> 브라우저는 HTML과 JS를 연결 -> 상호작용(버튼 클릭,등)가능해짐 => 수화(Hydration(수분 공금))이라고 부름 
=> FCP 에서 수화가 완료되는 순간까지를 TTI라고 부름
4. 사용자가 페이지 이동 요청할 경우 클라이언트 사이드 랜더링 방식으로 React와 동일하게 진행됨(브라우저에서 JS를 실행하여 컴포넌트를 교체)
=> 사전 랜더링 기법을 사용하여 CSR의 단점을 개선하고, 빠른 페이지 이동과 같은 React의 장점은 그대로 계승하여 단점을 개선하고 장점을 채용함

랜더링?
1. 자바스크립트 코드(React 컴포넌트)를 HTML 컴포넌트로 변환하는 과정 -> JS 랜더링
2. HTML 코드를 브라우저가 화면에 그려내는 과정 -> 화면 랜더랭
